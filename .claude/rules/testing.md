# Test code invariants

* Import `test/bootstrapTests.js` in every test file — it registers the root hooks and the `expect` / `testTimeout` globals — and open the file-level `describe` with `this.timeout(testTimeout)`; the root hooks in the bootstrap set the same timeout themselves.
* Never assume an empty cluster inside a `describe`: most `describe` blocks seed their own fixtures in a `beforeEach` (e.g. `static search()` in `test/lib/BaseModel.test.js` indexes two users and two documents). Read the enclosing `beforeEach` before asserting counts or orderings, and make new fixtures distinguishable (unique ids, names or a filtering query) instead of relying on `match_all` totals.
* Every tenant a test sends to Elasticsearch starts with `odmtest` (`odmtest`, `odmtest1`, `odmtestdupa`, ...) and a wildcard tenant is written as `odmtest*`, never `*` — the bootstrap only ever deletes inside that namespace, so anything written outside it both survives the cleanup and pollutes the next run. A bare `*` tenant is reserved for the tests asserting that `__checkIfFullySpecified` throws, which never reach Elasticsearch; the same goes for the tenants of the pure class-manipulation tests (`myTenant`, `test*test`).
* Write only fields present in the strict mappings created by the bootstrap `before` hook — `odmtest_users`: `status`, `name`, `fullname` (keyword); `odmtest_documents`: `documentTitle`, `html` (keyword) and `text` (text). Use an unmapped field deliberately when a test needs a per-item 400.
* Create an index a test needs under a dash-free `odmtest<tenant>_<name>` alias — `bootstrapTest.createIndex(alias, uuid)` for a dynamic mapping, the raw `bootstrapTest.client` for an explicit one — and remove it in a `finally` block or in the `afterEach` of the describe owning it (`bootstrapTest.deleteIndex` or `client.indices.delete`); a leaked index leaks into the wildcard searches of later tests.
* Call `bootstrapTest.resetFixtureIndices()` in a `finally` from any test which deletes, re-aliases, clones or re-settles `odmtest_users` or `odmtest_documents` — the root `beforeEach` only wipes documents, so an unrestored fixture index silently changes the ground under every later test of the run.
* Restore global state a test replaces (`setClient`, `setLoggerConfig`, `setLoggerUidFunction`, `setConfiguration`, a stubbed `esClient.client`) — in a `finally` block for a one-off swap, in the `afterEach` of the describe when it swaps repeatedly; take the ES URL from `bootstrapTest.nconf.get(...)` with the `es:url` key, never from a literal.
* Elasticsearch is never mocked except for the failures it cannot be asked to produce (the 429 retry, the 413 bulk splitting, a malformed response stream): swap `esClient.client` for a stub holding just the called methods and restore the original in a `finally` block. Reach for it only when no scenario against the real cluster reproduces the branch.
* Make optimistic-concurrency scenarios independent of `_seq_no === 0` (a legitimate value of the first document written to an index): run them against a bootstrap fixture index, whose sequence numbers never return to zero because the root `beforeEach` deletes documents and not the index, or write the document at least twice before provoking the conflict — unless zero is the point of the test.
* Write through the raw client with `refresh: true` into the two bootstrap fixture indices — they are created with `refresh_interval: -1`, so an unrefreshed write never becomes visible; the library's own writes refresh by default. An index created through `bootstrapTest.createIndex` refreshes on the ES default instead, so a test observing an unrefreshed write has to create its index through the raw client with `refresh_interval: -1` of its own.
* Nothing else may touch the `odmtest*` indices while a test run is in progress — the root `beforeEach` deletes every document in that namespace before each test.
* The suite deletes indices by wildcard, so the cluster must run with `action.destructive_requires_name` disabled.
